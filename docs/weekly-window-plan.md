# 七天限额窗口实现方案

2026-09-10。已按用户确认的 [最近一个月清单](weekly-window-review-20260910.md) 实施，代码及真实库验证见 [实现验收](weekly-start-validation.md)。此方案替代 `weekly-reset-plan.md` 的相邻观测重置分类。

## 口径

固定筛选订阅主桶 `codex` 的 10,080 分钟窗口，不区分 primary／secondary。旧结构取 secondary，新结构取 primary；不纳入五小时、零时长和 Spark 等额外模型桶。检查的是来源提供的总时长，不是距离截止的剩余时间。

历史条目表示一个已开始使用的七天窗口及其最后观测用量。额度归零后可能长时间没有消息，截止随查询滚动；直到首次使用才固定为一周后。因此额度恢复时间、首次观测和固定窗口起算时间必须分开。

## 归并规则

1. 保留原始额度事实及文件、行号、账号和 turn 证据，排除继承、fork 回放、其他任务的 turn 副本、过期及不合理未来窗口。同一明确账号、同一时刻出现相差超过一分钟的截止值时，作为冲突排除。
2. 对正用量观测按截止排序，以组内最早截止为固定锚点，归并最多 60 秒内的偏差。不会连续吸附而无限扩大组范围；不按日期合并，所以同一天相隔较远的新窗口各自保留。该阈值沿用用户已核对清单的归并方法；目前真实秒级偏差可被覆盖，不能宣称适用于未验证的任意上游时钟偏差。
3. 正用量中观测次数最多的截止秒值作为稳定截止；同次数取更早秒值，保证乱序插入结果一致。无正用量的单独零值不建立窗口，也不改变稳定截止。
4. 将正用量截止范围前后 30 秒内的零值并入现有窗口，以保留首次观测。更早的空闲滚动零值仍留在事实表，不生成空周期。
5. 同截止的 1%→0%→1% 或持续回落不拆窗口。最后观测与峰值分别保存；最新同刻值矛盾时，最后百分比为空并保留冲突计数。
6. 窗口起算时间固定标为推算值：`startedAtInferred = scheduledResetAt - 604800`。不把它称为手动重置发生时间。
7. 对账号明确的正值→零值→不同截止的新窗口正值序列，单独保存首次归零观测 `recoveryObservedAt`。例如 09-10 的归零观测为 08:08:27，起算为 08:23:40。未知账号不强行建立跨窗口的恢复关系，也不根据百分比下降确认手动操作。

## 账号与查询

- 全局按上述规则归并全部窗口证据，避免未知日志与同截止 API 观测各显示一条。记录明确出现过的账号列表和未知账号观测数量；这不等于将未知日志归给某个账号。
- 指定账号时，在归并前仅选择该账号的明确观测。未知账号查询则只选择未归属观测。三个范围的缓存分开，不能先取全局最高／最后值再附上账号标签。
- 多账号相同截止在全局属于合并证据视图，不把全局条数当作账号周期总数；账号级数据以指定账号查询为准。
- 日期筛选、排序、分页都按推算起算时间。包含正在使用的已固定窗口，不等预计截止后才出现。当前实时面板仍展示所有额度类型，与历史窗口独立。

## 数据结构与性能

`weekly_limit_observations` 原始事实不变。v9 仅清空旧派生窗口缓存，给 `weekly_limit_cycles` 增加 `query_scope` 及范围／起算索引；不备份、不删除 token 或金额。缓存 `event_at` 列保存推算起算时间。

`WeeklyLimitWindow` 输出：`id`、可空 `accountID`、`scopeKey`、`limitID`、`startedAtInferred`、`scheduledResetAt`、`firstObservedAt`、`firstPositiveAt`、`lastObservedAt`、可空 `lastUsedPercent`、`peakUsedPercent`、`observationCount`、`conflictingObservations`、`unknownAccountObservations`、`observedAccountIDs`、可空 `recoveryObservedAt`、`sourceJSON`。没有终态或路由证据的最终百分比、周期 token 和金额保持未知。

SQLite 临时表只物化数值和证据 ID，按截止秒值汇总后才把统计点交给 Swift；来源 JSON 只按主键读取。Swift 不加载全量日志观测。窗口结果按查询范围缓存，观测或 turn 归属变化使版本失效；同一范围的结果在单事务中发布，失败回滚后可重试。代表截止或更早证据变化时，能够唯一匹配的既有窗口复用 ID。

## 已验证

- 真实库最近一个月输出 12 个窗口，起算和稳定截止与确认清单逐秒一致；前 11 个窗口的最后百分比一致，当前窗口用量随新日志更新。
- 9 月 7 日 10:28 轨迹不再因几秒偏差重复；15:58 的另一条七天轨迹保留。
- 130 项测试通过，包括真实日志脱敏抽样、零值空闲、同日多窗口、截止抖动、乱序、同刻冲突、账号隔离、缓存失败回滚和稳定分页。
- 尚未取得的账号和真实手动重置时刻仍保持未知；已确认的是窗口归并和观测数据，不是所有窗口归属及最终账单。
