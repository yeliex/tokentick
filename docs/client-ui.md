# TokenTick 客户端 UI 方案

日期：2026-09-09

目标平台：macOS 26+。实现使用 SwiftUI、系统表格、Swift Charts 和原生窗口；样式参考 shadcn Luma 与 Shuttle 的原生界面。数据口径以 [需求文档](requirements.md) 为准。

## 1. 整体方向

这是一个以查询和核对为主的桌面统计工具。主窗口负责分析，菜单栏提供轻量入口；不把完整仪表盘塞进菜单栏。

- 中性、安静、可读。品牌颜色用于少量强调和图表，不将图标背景渐变铺满窗口。
- 保留系统侧栏、工具栏、滚动、排序、选择和焦点行为。
- Luma 的圆角和柔和层级用于内容分组；避免每个数据单元都变成卡片。
- 数据优先展示总量、变化和归属；来源证据放在可展开详情内。

图标继续使用已定稿的「用量环 · 分格」：浅色暖白琥珀、深色石墨薄荷。菜单栏使用同一单色模板，始终只放一个图标。

## 2. 窗口与信息结构

主窗口建议初始尺寸 1120 × 760，最小 860 × 580；侧栏约 210pt。大窗口可展开 300–360pt 的详情检查器，小窗口默认收起。具体尺寸是首版设计值，可按真机可读性调整。

```text
┌─────────────────────────────────────────────────────────────────┐
│ 系统窗口控制       当前页面             日期范围 · 筛选 · 同步    │
├──────────────┬───────────────────────────────────┬──────────────┤
│ 用量         │ 页面标题 / 查询条件                │ 检查器       │
│   总览       │                                   │ 按需展开     │
│   每日用量   │ 当前维度的统计、趋势、列表           │              │
│   任务       │                                   │ 分项用量     │
│   项目       │                                   │ 采用的价格   │
│              │                                   │ 来源证据     │
│ 记录         │                                   │              │
│   额度周期   │                                   │              │
│   数据状态   │                                   │              │
└──────────────┴───────────────────────────────────┴──────────────┘
```

使用 `NavigationSplitView` 组织侧栏与内容，`.inspector` 展开右侧证据，`Settings` 单独呈现偏好设置。侧栏使用轻量原生行，不显示重复小图表或大量统计数值。

当前工程已接入真实统计查询、预设日期、同步进度、分页表格、趋势和汇总检查器。本文描述的完整交互仍按 P5 推进；搜索、排序、交叉筛选、自定义日期及请求级证据尚未完成，没有用模拟数据填充运行中的 App。

## 3. 各页面内容与交互

| 页面 | 默认内容 | 核心操作 |
| --- | --- | --- |
| 总览 | 所选日期范围的 tokens、已知金额、未定价用量；每日趋势；模型／项目贡献 | 切换日期和 token／金额；点击某日或项目进入对应筛选 |
| 每日用量 | 趋势与日表；日期、tokens、已知金额、未定价量 | 选中日期后查看当天模型、任务与项目贡献 |
| 任务 | 标题、最新项目、活跃时间、tokens、金额；标题／ID 搜索 | 排序与选择；检查器显示模型分项和请求来源 |
| 项目 | 最新项目名及其用量、金额和趋势；明确的“未知项目”项 | 选中项目查看关联任务及按日分布 |
| 额度周期 | 当前与历史窗口；观测百分比、重置时间、已采集 tokens 和已知金额 | 选择窗口与 limit bucket；核对最后观测时间 |
| 数据状态 | 日志、价格、服务端三个来源的最近成功时间、进度和缺失 | 重试失败来源；检查未定价模型、冲突与未归属差额 |

模型作为总览构成和通用筛选，不先增加独立顶级页面。任务关系树、对话正文和 fork 历史图不进入初版客户端。

### 总览布局

```text
总览                                           最近 30 天 ▾

Token 用量                已知金额                未定价用量
—                         —                       —

每日趋势                                   Tokens / 金额
┌─────────────────────────────────────────────────────────┐
│                  真实统计接入后绘制                       │
└─────────────────────────────────────────────────────────┘

模型构成                         项目贡献
按 tokens / 已知金额切换          按贡献排序，点击后查看任务
```

“—”仅表示尚无数据或无法确认，不表示零。此线框不包含虚构的统计数值。

### 详情检查器

按“归属 → token 分项 → 单价与金额 → 来源”排列。默认只显示当前选中对象的内容，原始统计字段通过展开区查看。

- 归属：任务标题、任务 ID、项目；模型及 Fast／长上下文标记。
- 分项：输入、输出、缓存读取、缓存写入、推理；说明子项包含关系，避免用户自行相加。
- 金额：本次采用的输入／输出／缓存单价和分项金额；单价标明 USD／百万 tokens。
- 来源：日志文件名、rollout ID、行号，或服务端日期桶；路径可复制，源文件还存在时才提供定位操作。

## 4. 菜单栏与窗口行为

菜单栏始终只显示 18pt 模板图标，无数字后缀。点开后提供今日 tokens、已知金额、最新额度窗口和最近同步状态的简短摘要，底部是“打开 TokenTick”“设置…”“退出 TokenTick”。

主窗口用于深入查询。关闭主窗口后，菜单栏仍可打开主窗口；退出才结束应用。骨架使用 `WindowGroup`，允许系统标准窗口行为；后续可根据实际使用再收敛为单分析窗口，不先加入复杂窗口管理器。

额度未知显示“暂无额度数据”，不画 0% 进度。模式或金额未知不显示貌似完整的汇总。菜单现已读取今日统计、最近额度观测和同步状态，始终保留单个模板图标。

## 5. 视觉与组件

| 要素 | 首版方向 |
| --- | --- |
| 字体 | 系统字体；页面标题约 22–28pt；正文 13–14pt；表格数值使用等宽数字 |
| 间距 | 页面约 24–32pt；内容分组 20–28pt；表格保持原生紧凑密度 |
| 圆角 | 分组表面约 16–20pt；小控件遵从系统样式，避免全局统一成胶囊 |
| 表面 | 自适应中性色，浅边框，轻微分层；不把根窗口刷成固定白色 |
| 图表 | Swift Charts；低饱和度配色；选择、线型或标记辅助区分，不只依赖颜色 |
| 颜色 | 继承品牌的琥珀与薄荷倾向，但正文与状态使用系统语义颜色保证对比 |
| 动效 | 只用于选择、检查器及内容状态过渡，遵守减少动态效果设置 |
| 图标 | SF Symbols 表达功能，品牌图只用于应用身份与适量空状态 |

与 Shuttle 对齐的是柔和圆角、主次文字、分组表面和清楚的按钮状态；不复制其授权流程或强行复用与统计无关的组件。

本次图标接入范围：应用包默认浅色 ICNS；内容品牌图按系统明暗外观选择；菜单栏模板由系统着色。深色 ICNS 作为已定稿资源保留，尚未实现 Dock／Finder 应用图标的系统级自动切换，后续验证 macOS 26 的图标打包方案后接入。

## 6. 筛选与状态规则

- 日期：今天、最近 7 天、最近 30 天、自定义；查询条件始终可见。日表明确使用哪个统计时区。
- 任务／项目／模型筛选改变查询条件，不对已加载的有限分页数组做伪全量统计。
- 同步时保留旧结果，状态旁展示最近成功时间；首次加载才显示加载占位。
- 缺少数据、确实为零、部分未定价、来源不可用分别呈现。
- 金额标签默认“已知金额”；只有当前范围完整计价时才允许简化为“金额”。
- API 日差额使用“未归属用量”，说明其无法分配模型或任务；不能给出推测金额。
- 周期统计明确显示“已采集”，最后观测百分比不冒充周期最终值。
- 原始 token 精确值可选中和复制；紧凑缩写仅用于概览，详情提供完整数值。

## 7. 设置

设置窗口后续分为通用、数据来源与存储：

- 通用：统计时区、跟随系统的外观；登录时启动作为后续明确功能，不在骨架阶段开启。
- 数据来源：Codex 数据目录、账号和服务端可用状态；价格最近同步时间。
- 存储：数据位置、容量、备份及显式重建操作；结构迁移自动管理。

当前设置提供时区、Codex 数据目录、数据库位置、Finder 定位和缓存重建。容量、备份列表及目录选择器仍待补齐；不提供尚未实现的登录启动开关。

## 8. UI 验收

- macOS 26 明暗外观、860pt 最小宽度、大窗口和高分辨率下均可读。
- Tab、方向键、菜单快捷键及 VoiceOver 可操作；数字／图表状态不能仅用颜色传达。
- 切换页面和选择明细不导致重复全量扫描；列表分页，图表按范围聚合。
- 菜单栏只有一个图标，点击后可以打开主窗口和设置。
- 无数据时不展示假数值；部分金额、日差额、周期覆盖范围在相应上下文解释。
- App 与 CLI 使用相同条件的查询结果一致。

## 当前实现与验证边界

- 应用级 `ApplicationModel` 管理连接、同步与菜单摘要；每个窗口的 `DashboardModel` 只保存当前统计结果和分页，不持有历史请求全集。
- 总览使用真实日缓存绘制 Swift Charts；金额全部未知时显示无金额数据状态，不补零柱。每日页面共用趋势组件；任务标题与项目使用最新缓存映射。
- 汇总检查器能显示精确 token 分项和已知金额；尚不能展开请求记录、Fast／长上下文与源日志行。任务、项目和每日之间的交叉导航仍待实现。
- 数据状态支持独立重试日志／价格／API、未定价模型汇总、最近日桶和缓存状态。额度查询按观测时间排序，菜单只读取最近一次账号快照中存在的窗口，防止提前 reset 或缺失字段恢复成旧窗口。
- App／CLI 已构建并完成真实本地同步与中断恢复核对。Computer Use 因 Node runtime 无法启动仍不可用，点击、焦点、明暗外观与截图没有完成验收；运行进程不能替代这些验证。
