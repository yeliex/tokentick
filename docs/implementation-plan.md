# TokenTick 实现计划

日期：2026-09-09

范围：macOS 26+ 原生 App、同工程 CLI、数据层及首版客户端。产品需求见 [需求文档](requirements.md)，交互见 [UI 方案](client-ui.md)。本文件是后续实现计划，不代表所有阶段已经完成。

## 1. 当前交付 P0：可运行工程骨架

- `TokenTick.xcodeproj`，App `TokenTick` 与命令行 `tokentick` 两个共享 scheme。
- Swift 6，两个 target 最低 macOS 26.0，App 与 CLI 共用本地 `TokenTickCore` 模块，源码仍在 `TokenTick/Core`。
- 主窗口、原生侧栏、独立设置窗口、仅图标的菜单栏入口；统计页面均为无数据状态。
- 接入现有图标：应用包使用定稿浅色 ICNS；应用内容的品牌图支持明暗外观；菜单栏使用模板资源。
- P0 的 CLI 仅提供帮助／版本；P2 已加入 `scan`、`usage` 和基础 `status`，详见执行进度。
- `script/build_and_run.sh` 统一构建与运行，Codex Run 按钮指向该脚本。
- P0 时尚未接入数据层；目前 P1/P2 已加入 GRDB、迁移、本地扫描与 SQL 聚合，P3 已接入价格同步与计价，P4 已接入服务端统计采集及多维度缓存。整体同步、客户端数据绑定、正式分发签名和系统级深色 App 图标切换尚未完成。

P0 验收：两个 scheme 构建通过，App 可以启动并切换侧栏、打开设置；CLI 版本与帮助正确，未知命令退出码为 2；主窗口使用现有图标，菜单栏不显示数值。

## 3. P1 必须先解决的口径

1. 请求级记录与累计事件并存时的优先级；累计回退或重置不能误记为负用量。
2. 普通、fork、revert、子任务复制历史的所有权与请求去重键。
3. input／cache-read／cache-write 和 output／reasoning 的包含关系。
4. 日统计时区、价格 UTC 日期和 API 日期之间的关系。
5. Fast 和长上下文是否有明确证据；未知模式如何影响可计算金额。
6. 源日志归档、压缩或删除后，已入库事实与重新扫描的关系。

这些结论落入可重复运行的 fixtures 和断言，不能仅写在解释文档里。fixtures 只保留统计事件、必要的元数据和边界，不包含对话正文或账号凭据。

## 6. 分发与平台约束

- 以 macOS 26 为最低部署版本，不为更旧系统维护降级界面。
- 本地开发使用 ad-hoc 签名。当前 App Sandbox 关闭，以便后续读取用户本地 Codex 日志并与 CLI 共享数据库；此配置对应直接分发方向，不承诺 Mac App Store 上架。
- 正式发布前配置 Developer ID、公证及打包，不在工程初始化时猜测用户的签名团队。
- CLI 单独的 scheme 输出独立可执行文件；安装或嵌入 App 的策略在 P6 决定，不写入用户系统路径。
- 当前开发机为 macOS 27 / Xcode 27；以 26.0 部署目标构建不能替代 macOS 26 真机验收。

## 7. 完成标准

只有 fixture、真实本地抽样和跨入口查询均能解释 token 与金额，且迁移不会丢失历史，才视为数据层完成。每个阶段提交范围明确、通过对应检查后再进入下一阶段；不以图表看起来完整代替数据正确。

### P2 本地采集交付

- CLI `scan` 共用 Core：发现活动／归档目录，JSONL 按字节续读，Zstandard 原生流式解码。压缩表示变化时重扫并去重，已完成且未变化的压缩文件跳过。
- `rollout_id` 作为游标身份；归档只更新位置；文件替换／截断保留旧请求并重扫。多份同身份文件先做流式完整内容摘要，不一致时报告冲突，不任意选择。
- 每 512 行提交用量和解析状态，崩溃不会产生超前游标；末尾半行不提交；未知统计结构／坏行停止该文件并报告位置。
- 标准 envelope 中的正文和工具输出直接流式跳过，因此大工具结果不会占用整行内存或阻止后续统计；统计／未知结构单行上限为 16 MiB，Zstandard 窗口上限为 128 MiB。
- 请求级 `token_usage_record` 优先使用 response ID；相邻累计事件与请求记录对齐，旧记录补齐 ID 不重复计数。旧事件采用对话、轮次、事件时间和完整用量事实的摘要，不使用路径、行号或单独 ordinal 去重。兼容别名保存在 evidence_json，并以 v2 迁移建立查询索引。
- 明确 ordinal 边界排除 fork／子任务继承；位于继承区的父 session_meta 不覆盖子任务身份；无 ordinal 的旧 fork 使用来源创建时间判断，缺少有效时间则暂停并报告。无法从旧日志恢复的请求身份不包装为 API 级精确账单。
- 来源中的模型、Fast 依据、模型上下文窗口和原始 token 分项保留；未知金额／模式／账号保持 NULL。真实计价尚未接入。
- 只读 Codex `state_*.sqlite` 中的任务 ID、title/name、关联项目名；项目 ID 尚未回填时，读取桌面缓存中的显式项目分配、无项目标记和工作目录提示。路径只用于匹配已保存的项目根，不从目录名发明项目名；冲突归属保持未知。分批更新最新映射，不读取正文／preview。
- `usage --group day|thread|project|model` 在 SQLite 聚合，只返回有界结果；日分组当前为 UTC。统计缓存尚未启用，明细变化会原子标记缓存脏状态。

仍待后续阶段：历史价格和金额、API／额度记录、缓存重建与查询条件、文件通知、App 数据绑定。`status` 当前仅输出表记录数，`scan` 不包含网络同步。

### P3 历史价格与分项金额交付

- `sync-prices` 使用原生 URLSession 请求 models.dev，HTTP 成功、完整解码后才在同一事务写快照和当日成功标记；响应上限 32 MiB。当天已成功同步直接使用缓存；失败不写零价、不清空历史。
- 只解析 OpenAI provider；保存原始 cost／experimental 模式字段，价格数字使用 Decimal。没有 cost 的模型也保留全 NULL 快照，报告 missingPriceModels。
- 快照按 `(model, UTC 日期)` 保存；价格、阈值和适用规则不变时不追加。名称和 JSON 字段顺序不影响比较。未支持的多阶梯保留原始价格数据，不选取某一档冒充完整规则。
- 普通、Fast、长上下文和已核验模型的组合计价；GPT-6 Astra 与 GPT-5.6 系列组合依据官方价格表，其他模型不从两行价格盲目相乘。
- 普通输入 = input − cache-read − cache-write；reasoning 不额外收费。每个分项以 Decimal 计算，银行家舍入到整数纳美元，总金额为分项之和。分项不完整时保留已知金额，总金额 NULL；全部已知为零才可得到零总额。
- 新请求入库时使用已有历史价格；`reprice` 分批重算已有记录、按来源证据补齐可验证的 Fast 标记并原子标记统计缓存失效。未知模式、缺失历史价格、无模型、缺少分项、非法计数和溢出分别报告。
- `prices` 输出 USD／百万 tokens 单价；`usage` 的已知金额包含可算的部分金额，同时显示未完整定价的请求 tokens。没有任何可定价非零分项时，不把已知的零分项包装成零总费用。
- 修复 TokenTick 自有数据库从 WAL 备份恢复、但不存在 sidecar 时的打开问题：预检查连接允许 SQLite 创建其内部 WAL／SHM，业务 schema 仍在确认兼容前只读。Codex 来源数据库继续只读。

### P4 第一部分：API 事实采集

- 基于本机 Codex CLI 0.152.1 生成的实验性 JSON schema 实现适配，真实调用确认 `account/usage/read` 与 `account/rateLimits/read` 可用。
- `CodexAPIClient` 启动短期 stdio app-server，初始化后读取统计并关闭；App 和 CLI 共用实现。认证由 Codex 管理，不复制认证文件、不创建 TokenTick 常驻 daemon。可指定 Codex 可执行文件和数据目录。
- 每个 RPC 限时 30 秒、单条响应上限 4 MiB；跳过通知，支持取消，关闭时清理子进程。服务端错误只输出错误码，避免把任意服务端错误消息写入 UI／日志。
- 每日响应没有账号字段，前后读取自带账号 ID 的额度响应；未知账号或切换时不保存日桶，额度仍按其自带账号保存。多额度 map 优先，缺失 map 才回退单额度；不把 legacy 与 multi 重复保存。
- 日桶按账号＋原始日期更新，缺失／空数组不清空历史，不同账号不合并；旧观测不覆盖新观测。非法日期、重复桶和负数拒绝写入。摘要和完整统计响应存入内部元数据；各额度窗口保留对应来源片段。
