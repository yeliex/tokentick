## 周额度修复

真实观测揭示：只凭 `resets_at` 改变生成历史候选，会把额度截止时间漂移误当成重置。修复前历史前 10,000 行中有 2,642 行属于零用量的待确认变化。

现仅在跨过原计划边界且重置时间推进，或已用百分比回落时生成候选。提前回落即使重置时间不变、已经产生新用量也能识别；账号不明确则保留待确认。仅截止时间漂移时保留原观测，不生成重置历史。

同一真实副本修复后返回完整 3,829 条候选（无下一页）：自然边界 3,072、账号明确的疑似提前重置 1、未知归属回落 756；零用量漂移候选为 0。这些包含不同任务各自的未知账号证据，不能称为 3,829 个独立账号周期，也不能累计百分比。

`LimitQueryTests` 补充零及非零用量的截止时间漂移、同一截止时间下百分比未降至零的提前重置；与 `UsageStoreTests` 合计 11 个测试通过。数据库新版本拒绝打开时，现在明确提示更新 TokenTick，不再只显示错误编号。

## 接口及分发

- 干净 Release 构建、ZIP 解压、SHA-256、App／CLI 严格签名验证通过，两个可执行文件均只含 arm64。使用 ad-hoc，无付费 Developer Program 和公证。
- 解压后的 CLI 通过真实接口读取 3 个额度窗口，包含周额度、五小时额度及额外额度桶。SQLite 只保存其中 2 个周额度观测，实时完整快照不进入持久同步报告。
- 独立空价格库实际请求 models.dev 成功，保存 48 个模型的首份快照；4 个图像模型仍明确缺少 token 价格。已有库同日再次同步直接返回已同步，不重复请求或新增价格。
