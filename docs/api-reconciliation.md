核验日期：2026-09-10。目标仍是补齐跨设备用量，当前没有足够证据计算差额。

## 已确认的接口

[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server#7-token-usage-chatgpt)说明 `account/usage/read` 提供账号 token 活动摘要和可为空的每日桶；每个桶只有 `startDate` 与整数 `tokens`。本次实际打开的官方页面没有定义日桶时区、缓存／推理包含关系或账号 ID 字段。不能把 OpenAI API 平台 Usage API 的定义套用到此接口。

本机 Codex CLI 为 0.152.1。本次只读探测在前后两个额度响应的账号一致时，取得 196 个日桶；实际字段仍是 `startDate` 和 `tokens`。完整响应留在忽略目录 `.build/research/api-semantics-20260910/observations.json`，脱离账号值的字段摘要在同目录 `summary.json`。

本机生成的实验性协议还支持向同一方法传入 `threadId`，返回可空 `threadUsage`，包含估算 credits／USD 及按模型、speed 分组的 tokens 等字段。该协议对字段的定义不等同于服务端可用性。本次针对当前真实任务调用成功，但 `threadUsage` 为 null，不能据此补充任务用量或金额。原始生成协议位于 `.build/research/app-server-schema/v2/GetAccountTokenUsageResponse.json` 和 `NullableGetAccountTokenUsageParams.json`。

## 尚缺的对账条件

| 条件 | 当前证据 | 影响 |
|---|---|---|
| 日桶的起止时刻与时区 | 日期字符串，没有时区字段或官方日边界定义 | 不能与本地按所选时区的日统计直接相减 |
| token 口径 | 只有总数，没有缓存、输入、输出、推理定义 | 无法证明与本地请求总 tokens 是同一指标 |
| 历史请求账号 | 本地请求记录和会话元数据缺少可用账号证据 | 不能把当前登录账号套给历史请求；切换账号后更不能复用同一份本地总量 |
| 服务端覆盖范围与延迟 | 未确认跨设备覆盖、终态和回补行为 | 差值为正不等于已证实存在未知对话用量 |
| 周期路由 | 额度窗口只有时长、reset、百分比；本地缺少请求所属额度桶 | 不能将全部模型消耗分摊到每个额度周期 |

因此继续保存服务端日桶及统计来源，保持独立查询；不创建 API 差额记录，不通过百分比反推 tokens／金额。未来得到口径和账号证据后再实现对账，不能把“当前没有差额”标为该需求已经完成。

## 同步状态和账号隔离

- App 与 CLI 经同一个 API 同步入口执行可执行文件解析、读取和结果保存。找不到 CLI、初始化失败或整个接口失败，也保存带时间的来源状态；取消不记录成服务端失败。
- API 状态独立于最近一次整体／本地同步，后续本地成功不会掩盖 API 错误。较旧观测不覆盖较新成功或失败；已有日桶、额度和本地用量保持原有保留规则。
- 成功状态包含额度响应确认的账号 ID。菜单只读该账号最近快照中的额度，不能从其他历史账号借用 codex 窗口。失败时账号保持未知；历史额度仍可在额度页查询。
- 新增的状态账号和时间字段可为空，兼容旧 JSON；旧状态没有证据时不猜测账号。无需改变业务表或添加数据库迁移。
